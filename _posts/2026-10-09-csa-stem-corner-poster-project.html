想象一下：一位从没学过 Java 的同学路过 STEM Corner，突然在你的海报前停下了脚步。30 秒后，他会记住什么？ 这次，你们来决定计算机科学在走廊里是什么样子。

AP Computer Science A STEM Corner · Hallway Poster 100 分项目作业 创意自由，标准清晰

🎯 你的任务：让路过的人也能读懂 CS

为学校 STEM 展示区设计一张与 Computer Science（计算机科学）有关的海报。你的作品将有机会真实展示在走廊里，观众不只是 AP CSA 同学，还有可能是完全没学过编程的老师和学生。

形式可以是知识图解、漫画、时间线、趣味挑战、人物故事，或你提出的其他好点子。不规定统一主题，也不要求人人画得像艺术家。

成功标准：别人愿意停下来 → 看得懂 → 带走一个有价值的 CS 想法。
Make someone stop, think, and learn something.

成绩说明：本海报是一次 Project 成绩（满分 100）。本课程的 Project 类别合计占总成绩 20%；不是说这一张海报单独占课程总成绩的 20%。

💡 没灵感？从这里开始

以下只是 idea starters（灵感起点），不是规定选题。你可以组合、改造，也可以完全不选它们。

01 · CONCEPT

用一张图解释一个概念

Classes vs. Objects、Java 的 pass by value、两个 references 指向同一个 object 会怎样？

02 · CHALLENGE

让观众来解题

Predict the Output、Find the Bug、三选一小挑战。别忘了提供正确答案和简洁解释。

03 · STORY

讲一个计算机科学故事

Ada Lovelace、Grace Hopper、一个改变了互联网的想法，或者编程语言背后的故事。

04 · EVERYDAY CS

把算法带进日常生活

地图导航为什么会推荐路线？搜索为什么这么快？生活中有哪些看不见的 algorithms？

05 · HUMOR

把技术笑点讲明白

Debugging 像破案？程序员最害怕的错误是什么？有趣可以，但不能只有段子、没有知识。

06 · YOUR IDEA

完全不同？更好

漫画、手绘、折叠翻页、视觉谜题……大胆提出方案，只要能安全、清楚地在走廊展示。

📌 创作自由，但有 5 条底线

  1. 真的与 CS 有关：不能只是科技风图案。海报必须传达至少一个具体、正确的计算机科学知识、思路或故事。
  2. 内容准确：出现代码，要检查逻辑与运行结果；出现事实与历史信息，要查证。不能为了搞笑把错误知识当成事实。
  3. 普通观众能看懂：有清楚的标题、主要信息和合理的阅读顺序。想象观众站在约 1–2 米外：第一眼知道这张海报讲什么吗？
  4. 适合公开展示：内容尊重他人、符合校园环境。借用文字或图片要注明来源；使用 AI 辅助可以，但必须自己核查并说明用途，遵守学校相关规定。
  5. 先获得批准再制作：老师要先确认选题、作品形式、尺寸和安装方案。请不要在批准前自行付费打印。
小提醒：QR code、翻页机关、互动设计都可以提案，但不强制。不能扫码时，海报本身也应该让人学到东西。

🛠️ 从想法到上墙：4 步完成

STEP 1 Idea & Proposal

选定主题，写短提案，并画一个粗略布局草图。

STEP 2 Get Approval

和老师确认方向，以及你自己的 10 分挑战目标。

STEP 3 Create & Revise

制作初稿，检查事实、代码、字数和远距离可读性。

STEP 4 Submit & Display

提交定稿和简短说明，老师确认后安排实际展示。

完成形式：默认每人独立完成。如果想两人合作，需要在提案中说明各自分工，并事先获得批准；合作作品须分别提交个人贡献说明。

最后交什么：① 已批准的 Proposal；② 最终海报（电子作品优先提交 PDF，同时保留可编辑源文件；手工作品提交清晰照片并按老师要求交实物）；③ 使用的资料/图片来源及 AI 工具说明（如有）；④ 2–3 句 Reflection：你改进了什么，为什么？

提案、初稿、定稿的具体截止时间和提交入口，以课堂通知为准；海报大小与布展方式在 Proposal 获批后确认。

📝 先交 Proposal，不是直接开画

提案不用写成长篇论文。用自己的话，把下面几个问题说清楚即可。重点不是你已经做完了什么，而是你打算让别人看懂什么。

查看一个合格的 Proposal 示例

标题：Two Names, One Object

主题：解释两个 Java object references 为什么可能指向同一个 object。

观众收获：即使没学过 Java，也能通过一张箭头示意图理解“两个变量不一定代表两个对象”。

形式：上半部分画两个遥控器控制同一台机器人；下半部分给出简短 Java 代码和预测结果。

自选挑战：设计一道有答案的 Predict the Output 小题，并请两位没学过 Java 的同学试读，根据反馈至少修改一次。

资料：课堂笔记、BlueJ 自己测试的代码截图。

📊 Rubric：100 分怎么算？

老师会提前公开标准，但你仍有创作自由。评分不是“谁画得最漂亮谁就赢”。理解、表达和完成质量更重要。

评分项目分值高质量作品的表现
CS Accuracy
知识准确性		30概念和术语正确；例子、代码或事实经得起检查；选题有实质性的 CS 内容。
Communication
表达与讲解		20标题抓住重点；不懂编程的观众也能抓住核心信息；内容简洁、解释清楚。
Visual Organization
视觉组织		10排版有层次；字体、图形与留白帮助理解；从走廊里看也容易阅读。
Planning & Execution
计划与执行		10按要求提交提案与定稿；回应反馈；资料标注清楚；作品完成度高。
Creativity & Impact
创意与吸引力		20呈现方式有自己的想法；能够吸引观众停留；创意确实帮助观众理解内容。
Student-defined Challenge
自定挑战目标		10提案中提出、并获得老师批准的具体目标被认真实现，有可检查的证据。
总分100准确 + 清楚 + 有想法 + 做到位
什么样的“自定挑战目标”才算好？

太模糊：“我要让我的海报很好看。”——无法客观检查，所有人都可以这么说。

更具体：“我要制作一张带有正确解答的 Java 找 Bug 挑战海报，并邀请两位非 CSA 同学试读，根据他们的反馈完成一次修改。”

你可以挑战自己：设计能被理解的互动题、做出清楚的对比图、采访目标观众并修改作品……难度和可行性由老师在制作前审核，不能在交稿后临时修改标准。
