Constructor 里发生了什么？

创建 profile1 时：

Constructor call
new GameProfile("Alex", 5, avatar1)

parameter a 得到的是 avatar1 中 reference value 的 copy：

avatar1 ─────┐
             ▼
          Avatar
             ▲
a ───────────┘

当 constructor 再执行：

Store the reference
avatar = a;

就形成：

avatar1 ──────────┐
a ────────────────┼──► same Avatar object
profile1.avatar ──┘
Java is pass by value.
当 argument 是 object reference 时，被复制的 value 就是那个 reference。

✓ AP 题怎么追踪 Reference？

代码变长以后，继续使用同一套方法。

第一步：数 new

Example
Avatar a1 = new Avatar("Knight", 80);
Avatar a2 = a1;
Avatar a3 = a2;

这里真正执行的 new Avatar(...) 只有一次。

第二步：数 object

1 个 Avatar object

第三步：画 reference

a1 ───┐
a2 ───┼──► Avatar object
a3 ───┘
Reference 的数量 ≠ Object 的数量。

Primitive 和 Object 放在一起比较

Primitive argument

score = 80
   │ copy
   ▼
x = 80

复制的是 primitive value。

Object argument

avatar1 ───┐
           ▼
        Avatar
           ▲
target ────┘

复制的是 reference value。

Java 的规则始终一致：pass by value。
区别只是被复制的 value 是 primitive value，还是 reference value。

TODO 3：healAvatar
Answer
public void healAvatar(Avatar target, int amount)
{
    target.heal(amount);
}

target 和 caller 中的 reference 指向同一个 Avatar object， 所以 target.heal(...) 修改的是共享 object。

tryToReplace
Answer
public void tryToReplace(Avatar target)
{
    target = new Avatar("Robot", 100);
}

执行重新赋值后：

avatar1 ─────────► Knight

target  ─────────► Robot

target 改变了自己保存的 reference。 caller 中的 avatar1 仍然指向原来的 Knight object。

修改 Object vs 修改 Reference 
target.heal(30)
→ 修改 target 指向的 object

target = new Avatar(...)
→ 修改 target 自己保存的 reference
